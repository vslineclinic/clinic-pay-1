## 기간 대사 모드 (한솔↔차트 · 여러 날)

월(기간) 단위로 내려받은 **한솔 거래내역 + 차트마감(수납)** 파일 2개만으로, 일자별
(한솔 `거래일` ↔ 차트 **`수납일`** — 진료일 아님) 카드·현금영수증 합계를 자동 대사해
**차이가 있는 날만** 짚어줍니다. 차이가 있는 날은 승인번호(결제메모)·금액 매칭으로
설명되지 않는 거래만 추려 보여주므로(보통 0~3건) 원인 확인이 빠릅니다. 일일마감은
필요 없습니다. 첫 화면의 `분석 모드 → 기간 대사`에서 사용.

하루 정밀 대사 모드에 여러 날짜가 담긴 차트마감/한솔 파일을 올리면, 구글시트에서
고른 날짜(또는 일일마감과 차트번호 겹침이 가장 큰 수납일) 하루로 자동 필터링됩니다.

## 접근 설정과 기존 구글시트 링크 연동

운영 주소: <https://vsline-clinic-pay2026.streamlit.app/>. GitHub → Streamlit 배포를 유지하며
GPT Sites로 이전하지 않습니다. 운영 Python은 3.13입니다.

아이디·비밀번호로 로그인합니다. 총괄관리자는 모든 지점, 지점 계정은 본인 지점만 이용합니다.
계정은 비공개 기록 시트의 **계정** 탭에 비밀번호 검증값으로 보관하며, 총괄관리자의
**계정 관리** 화면에서 지점 계정 생성·비밀번호 변경·이용 중지를 관리합니다.
이전 `APP_PASSWORD`나 기존 공용 암호 세션은 로그인 또는 총괄 권한을 부여하지 않습니다.
지출관리앱에서 이관한 계정은 기존 비밀번호를 유지합니다. 이관 후 두 앱의 계정 변경은 별개입니다.
운영 지점은 인천점·잠실점·엔디어트·강남점·일산점·압구정·마곡점 **7곳**입니다.
BW컨설팅은 지점 선택·지점 계정·기록 조회 대상에서 제외하며, 총괄관리자의 전체 지점 권한은 유지합니다.

개인 기기에서는 로그인 화면의 **로그인 유지 · 최대 180일**을 선택할 수 있습니다. 다음 접속은
저장된 기기 키로 복원하며, 비밀번호 원문은 쿠키에 보관하지 않습니다. 로그아웃하면 해당
기기 키를 취소하고, 비밀번호·소속·활성 여부를 변경하면 이전 로그인은 사용할 수 없습니다.
브라우저 설정이나 쿠키 삭제로 더 일찍 해제될 수 있습니다. 아이디·비밀번호 입력은 브라우저
비밀번호 관리자의 저장·자동완성도 지원합니다. 자세한 운영은 [장기 로그인](docs/PERSISTENT_LOGIN.md)을 참고하세요.

1. `.streamlit/secrets.toml.example`을 참고해 로컬 `.streamlit/secrets.toml` 또는
   Streamlit 배포 Secrets에 값을 설정합니다. 실제 암호·API 키·서비스 계정 개인 키는 Git에 넣지 않습니다.
2. 로그인에는 `HISTORY_SHEET_ID`와 `HISTORY_SERVICE_ACCOUNT_JSON`, **계정** 탭이 필요합니다.
   기존 기록 저장용 인증을 그대로 사용합니다. 암호화된 베가스 파일은
   업로드 화면에 암호를 입력하거나 선택 설정 `FILE_PASSWORD`를 사용합니다.
   코드에 내장된 기본 암호와 추측 암호는 제거했습니다.
3. 사용자 요청에 따라 **기존 링크 연동과 구글시트 공유 권한을 유지**합니다. Secrets에
   `[clinic_daily_sheets]`가 없으면 기존 6지점·7개 파일 주소를 사용합니다. 엔디어트는
   2026-06-12부터 새 파일을, 이전 날짜는 옛 파일을 선택합니다.
4. `[clinic_daily_sheets]`를 추가하면 **그 설정 전체로 대체**합니다. 기본 지점과 자동 병합하지
   않으므로 사용할 지점을 모두 적으세요. 빈 설정은 모든 기본 지점을 숨깁니다. 날짜별 파일
   전환은 `[["2026-06-12", "새 URL"], ["", "옛 URL"]]` 형식을 지원합니다.
5. `[gcp_service_account]`가 없으면 Google의 기존 공유 링크를 읽기 전용 GET으로 조회합니다.
   서비스 계정은 필수가 아닙니다. 이 설정을 추가한 경우에만 읽기 전용 Sheets API를 사용하며,
   인증 실패 시 링크 읽기로 우회하지 않습니다. 총괄관리자는 일일마감 파일 업로드도 사용할 수 있습니다.

지점 계정은 구글 일일마감을 본인 지점 링크로 자동 연결합니다. 다른 지점 선택과 일일마감
파일 업로드는 제공하지 않습니다. 기간 분석도 같은 지점으로 고정하며, 원본의 교차검증이
안 되는 자료는 지점 분석에 사용하지 않습니다. 연결이 없는 지점은 다른 지점 링크로 대체하지 않습니다.
누적 기록 조회·저장에도 서버에서 지점 권한을 확인합니다. 로그아웃·권한 변경 시 원본,
분석 결과, 다운로드·AI용 데이터와 캐시를 지워 다음 계정에 이전 지점 자료가 남지 않게 합니다.
설정과 운영 방식은 [`docs/BRANCH_ACCESS.md`](docs/BRANCH_ACCESS.md)를 참고하세요.

링크 연동은 매 조회에서 날짜 탭→gid를 확인하고 `export` CSV를 우선 사용해 머리글을
보존합니다. gviz 보조 경로는 첫 탭 대체 응답과 조회 중 변경을 검사하며, 없는 날짜를 첫 탭으로
대체하지 않습니다. 조회 주소와 다운로드 이동은 HTTPS Google 호스트로 제한합니다.
지원하는 날짜 탭 형식은 `26.06.02`, `06.02`, `6.2`, `26.6.2`, `2026.06.02`,
`26년 06월 02일` 등입니다. 앱 접근 암호는 구글시트 자체의 공유 권한을 바꾸지 않습니다.
압구정에서 사용하는 `26.10.13.`, `26년10월14일`, `26년7월2일`, `26년 03월9일` 같은
날짜 전체 형식도 정확히 일치할 때 읽습니다. 임의 메모가 붙은 이름이나 이웃 날짜는 대체하지 않습니다.

### 일자별 정산 기록과 월별 조회

하루 정밀 분석 결과는 별도의 비공개 기록 시트로 누적할 수 있습니다. 왼쪽 **정산 기록**에서
지점과 월을 선택하면 확인했던 날짜·합계와 채널별 차이·검증 건수·마지막 확인 시각을 봅니다.
같은 지점·날짜를 재정산하면 최신 결과 한 줄을 표시하며 이전 결과는 변경 이력으로 보존합니다.
합계 0원이어도 채널별·환자별 차이 또는 연결 검토가 남으면 **검토 필요**로 표시합니다.
단말기를 제공하지 않은 결과는 **단말기 미검증**으로 남깁니다. 기록 없는 날을 정산 누락으로
단정하지 않으며, 원본을 수정했으면 다시 정산해야 기록에도 반영됩니다.

영구 저장에는 `HISTORY_SHEET_ID`와 `HISTORY_SERVICE_ACCOUNT_JSON`을 한 번 설정해야 합니다.
새 기록 시트에만 기록 전용 서비스 계정을 편집자로 추가하며 기존 일일마감 공유·링크는 유지합니다.
계정 인증 연결이 없으면 로그인을 열지 않습니다. 총괄관리자의 일일마감 파일 업로드 방식은
정산 지점을 직접 선택합니다. 저장 실패 시 결과와 **저장 재시도** 버튼을 유지합니다.
환자 이름·차트번호·승인번호·원본 파일·메모·AI 보고서는 기록에 저장하지 않습니다.
기간 분석은 이 누적 기록에 포함하지 않습니다. 설정 및 운영 절차는
[`docs/RECONCILIATION_HISTORY.md`](docs/RECONCILIATION_HISTORY.md)를 참고하세요.

### AI 전송과 결과 보관

AI 분석은 실행 버튼을 눌렀을 때만 외부 Gemini로 요청합니다. 전송 데이터와 추가 질문의
등록된 이름·차트번호·승인번호·카드 말미를 분석별 토큰으로 바꾸며, 미리보기와 실제 전송은
같은 가명화 값을 사용합니다. 원본 자유 메모·거래내용 열은 AI 입력에 넣지 않습니다.
추가 질문에는 주민번호·연락처 등 불필요한 개인정보를 입력하지 마세요. 등록되지 않은
임의의 개인정보를 자유문장에서 완벽하게 자동 탐지하는 기능은 아닙니다.

결과의 원본 식별자는 서버가 화면/다운로드를 만들 때만 복원합니다. 금액·결제수단·시간은
분석에 남으므로 완전 익명화가 아닙니다. 외부 공급자의 처리·보존 조건과 계약은 운영자가
확인해야 합니다. `GOOGLE_API_KEY`의 기존 입력 화면 동작은 이번 변경에서 유지했습니다.

AI 캐시는 현재 브라우저 세션의 최근 결과 1건만 30분간 재사용합니다. 요청한 모델,
시스템/사용자 프롬프트 또는 폴백 정책이 바뀌면 다시 분석하고 실제 응답 모델을 표시합니다.
서버 디스크에는 새 보고서를 저장하지 않습니다. 기존 배포의 임시 디렉터리에 있는
`clinic_pay_ai_cache` 파일은 자동 삭제하지 않으므로 운영자가 배포 전 보관 필요성을 확인하고
직접 정리해야 합니다. 파일 다운로드로 저장한 결과에는 개인정보가 포함될 수 있습니다.

### 교차검증 — 타 지점/다른 날짜 파일 방어

차트마감(베가스)을 업로드하면, 선택한 **일일마감과 같은 지점·같은 날짜인지** `차트번호`
겹침으로 검증합니다(`cross_check_daily_patient`). 결과는 세 가지:

- **block** — 양쪽 모두 차트번호가 있는데 일치율이 기준(`CROSS_CHECK_MIN_RATE`, 기본
  **0.6=60%**) 미만 → **합계·통계를 일절 표시하지 않고** "다른 지점/날짜 파일" 안내만 노출
  (자료 선택 오류 방지이며 접근권한 검사는 아님).
- **warn** — 한쪽에 차트번호가 없어 대조 자체가 불가(예: 비표준 일일마감) → **경고만 하고
  분석은 진행**(표준화 전환기 편의). 표준 양식으로 입력하면 자동으로 block 검증이 적용됩니다.
- **ok** — 일치율 기준 이상 → 조용히 통과.

일치율 = `|두 파일 차트번호 교집합| / min(일마 차트수, 차트 차트수)`. 같은 지점·같은 날짜면
보통 0.9 이상, 다른 지점/날짜면 0에 가깝습니다. 기준값은 `app.py` 상단
`CROSS_CHECK_MIN_RATE` 한 줄로 조정(0.7/0.8 등).

### 일일마감 표준 양식 (★중요)

지점마다 마감 양식이 다르면 합계가 어긋납니다. 아래 표준 양식으로 통일하면 그대로 정확히
분석됩니다. 템플릿 파일: **`templates/일일마감_표준양식.xlsx` / `.csv`** (복사해서 사용).

- **헤더는 한 줄**, 셀 병합 금지. **1행 = 1환자/1거래**.
- 컬럼명은 아래 이름을 **정확히** 사용(띄어쓰기·줄바꿈 없이). 특히 `나만의닥터`는 붙여쓰기.

| 컬럼 | 필수 | 설명 |
|---|---|---|
| `내원순서` | 권장 | 방문 순서(숫자). 없으면 자동 번호 |
| `차트번호` | **필수** | 차트마감·한솔과 매칭하는 핵심 키 |
| `성명` | **필수** | 환자명 |
| `구분` | 권장 | `환불`/`취소` 표기 시 자동 분리·차감(금액은 양수로) |
| `카드` `현금` `이체` | 필수* | 결제수단별 금액(숫자만, 빈칸=0) |
| `여신티켓` `강남언니` `나만의닥터` `제로페이` `기타지역화폐` | 필수* | 플랫폼 결제 금액 |
| `알리페이` `위챗페이` `카카오페이` | 필수* | QR·모바일 간편결제(플랫폼합에 포함) |
| `간편결제(큐릭)` `바비톡` `닥터나우` | 필수* | 큐릭 QR 간편결제·플랫폼앱(플랫폼합에 포함) |
| `비고` 등 | 선택 | 추가 컬럼은 분석에서 무시(결제수단명과 겹치지 않게) |

\* 사용하는 결제수단만 채우면 됨. 대체 컬럼명 허용: `여신티켓`=`여신`, `기타지역화폐`=`기타-지역화폐`,
`위챗페이`=`위쳇페이`, `간편결제`=`간편결제(큐릭)`=`큐릭`, `나만의닥터`=`기타-나만의닥터`.
알리페이·위챗페이·카카오페이·`간편결제(큐릭)`·바비톡·닥터나우는 카드 단말(한솔)을 거치지 않는
QR·모바일·플랫폼 결제이므로 **카드가 아닌 플랫폼**으로 집계됩니다(제로페이와 동일 범주 →
`플랫폼합`·`총액`에 합산). 차트마감(베가스)이 큐릭 결제를 `간편결제(현금영수증)`으로 적어도
'현금영수증' 글자에 속지 않고 **플랫폼**으로 분류합니다(일일마감 `간편결제(큐릭)` 컬럼과 대칭).

- **시트 탭 이름 = 날짜**. `YY.MM.DD`(0패딩, 예: `26.06.02`)를 권장하나, 지점별 실측 형식
  (`06.02` / `6.2` / `26.6.2` / `2026.06.02` / `26년 06월 02일`(압구정) 등)도 자동 매칭합니다
  (`_candidate_tab_names`). 다른 형식이 필요하면 그 함수에 후보를 추가하면 됩니다.
- `총액`/`플랫폼합`은 앱이 결제수단 합으로 자동 계산하므로 넣지 않아도 됩니다.

> **등록 지점(인천·잠실·엔디어트·강남·일산·압구정) 안내**: 일부 시트는 차트번호가 `구분` 바로
> 오른쪽 열에 입력돼 있으나 **그 열 머리글 칸이 비어 있습니다**. 앱이 자동복구하므로 정확히
> 분석·교차검증되지만, 명확성·감사를 위해 해당 머리글 칸에 **`차트번호`를 직접 입력**해 두기를
> 권장합니다(자동복구는 안전망으로 그대로 유지).
>
> 결제수단 열 머리글(카드/현금/이체 등)은 시트에 입력돼 있으면 그대로 보존·인식됩니다(앱이
> 인증된 Sheets API로 머리글 행까지 읽기 때문). 단 일산·압구정처럼 **열 순서가 지점마다 달라도**(예:
> `이체·현금·카드…`) 머리글대로 정확히 분류합니다.

### 환불 정합성 검증 (유형C2 자동 진단 + 한솔 3자 판정)

차트마감(베가스)은 환불을 **원거래 전액취소(음수 행) + 재승인(양수 행)**으로 적고,
일일마감은 **본행 + 환불 행 차감**으로 적는다. 일마 본행에 이미 환불이 반영된
재승인액을 적고 환불 행을 또 차감하면 **환불 이중차감**(일마 net 과소)이 된다
(환불 이중차감 예시 — 일마 최종 수납액이 차트·한솔보다 환불액만큼 적게 집계).

앱은 유형C2(금액불일치)에서 차이가 환불 행 금액과 정확히 일치하면 `추정원인`에
**환불 이중차감/미반영** 진단을 자동 표기하고, 한솔(PG) 파일이 있으면 `한솔판정`에
**어느 원본을 검토할지** 안내한다:

- 승인 연결이 완전하면: 차트 결제메모 승인번호로 한솔 카드 net(취소 차감)을 환자에
  귀속해 차트/일마 중 일치하는 쪽을 비교하고, 불일치한 원본의 검토를 권한다.
- 일부만 연결되면: 전체 단말기 금액과 판단을 보류한다. 미연결 승인·취소의 순액이
  우연히 0이어도 환자의 전체 수납이 연결된 것으로 보지 않는다.
- 2순위(정황): 메모에 승인번호가 없으면, 그날 한솔 승인금액 목록(정상−취소 net)에
  차트금액/일마금액이 존재하는지로 지지 방향을 표시 — `승인번호 미링크` 명시.

이 진단은 UI(🔎 데이터 검증 탭·기간 분석 날짜별 검증)와 AI 진단 입력([데이터검증]
유형C2의 원인/한솔판정 컬럼), 검증 엑셀에 모두 반영된다. AI 프롬프트에도 R14(환불
표기 방식 차이 규칙)가 있어 이 진단을 그대로 인용해 결론을 낸다.

## 테스트

파서·매칭·합계대사·산출물의 정확도를 회귀 검증하는 pytest 스위트가 `tests/`에 있습니다.

```bash
pip install -r requirements-dev.txt
pytest
python scripts/smoke_streamlit.py
```

- `tests/conftest.py` — streamlit 경량 스텁 주입(설치 없이도 순수 로직 테스트 가능).
- `tests/factories.py` — 합성 원본 데이터(한솔/일마/차트) 빌더.
- `test_utils` / `test_parsers` / `test_matching` / `test_reconciliation` / `test_outputs`
  — 시간 파싱·결제수단 분류·승인번호 매칭·환불 net 처리·★★ 확정매칭·엑셀 산출 등을 검증.
- CI는 Python 3.11/Streamlit 1.36과 Python 3.12/최신 Streamlit에서 계산 테스트와
  별도 프로세스의 실제 AppTest를 실행합니다. 외부 시트·AI 호출은 모의 응답을 사용합니다.
