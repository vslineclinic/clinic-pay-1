# 기기 로그인 유지

로그인 화면에서 개인 기기에 한해 **로그인 유지 · 최대 180일**을 선택한다. 선택하지 않으면
기존처럼 현재 세션에서만 로그인한다. 브라우저 비밀번호 관리자를 위한 `username`과
`current-password` 자동완성도 제공한다. 비밀번호 관리자의 저장 안내는 브라우저가 결정한다.

## 저장과 만료

서버가 비밀번호 인증 후 256비트 임의 기기 키를 발급한다. 브라우저에는 이 키만 쿠키로
보관하고 비밀번호·계정의 비밀번호 검증값을 저장하지 않는다. 만료는 발급 후 최대 180일로
고정하며 재접속이나 화면 갱신으로 늘리지 않는다. 브라우저 정책·쿠키 삭제·사이트 데이터
정리는 더 이른 해제를 일으킬 수 있다.

쿠키는 `__Host-clinic_pay_remember`, `Secure`, `SameSite=Strict`, `Path=/`이며 Domain을
설정하지 않는다. 로컬 Streamlit v1 컴포넌트가 쿠키만 연결하고 외부 스크립트는 사용하지
않는다. JavaScript 쿠키이므로 HttpOnly는 아니며 브라우저에서 쿠키 사용을 막으면 일반
아이디·비밀번호 로그인으로 이용한다. 실제 암호는 이 컴포넌트로 전달하지 않는다.

서버는 복원과 보호된 작업을 실행할 때마다 기기 키와 최신 계정의 개정·활성 여부를 다시
조회한다. 역할과 지점은 브라우저가 보낸 값 대신 기존 계정 저장소에서 가져온다. 서버
재시작·재배포 뒤에도 같은 키를 검증할 수 있으며 분석 파일이나 환자 자료는 복원하지 않는다.

## 비공개 저장소

기존 `HISTORY_SHEET_ID`와 `HISTORY_SERVICE_ACCOUNT_JSON`을 사용하며 새 Secrets나 원본
일일마감의 공유 변경은 없다. 같은 비공개 기록 시트의 별도 `로그인기기` 탭을 사용한다.

```text
device_id, username, account_revision, token_hash, issued_at, expires_at, revoked_at
```

실제 기기 키는 저장하지 않고 전체 키의 SHA-256만 기록한다. 시각은 UTC ISO 문자열,
사용 중인 행의 `revoked_at`은 빈 문자열이다. Sheets가 마지막 빈 셀을 생략하는 응답도
처리한다. 로그아웃은 중지 행을 추가하며 같은 기기의 과거 사용 중 행을 다시 추가해도
해제가 되돌아가지 않는다. 헤더가 없거나 잘못된 경우 일반 로그인은 유지하고 기기 저장은
실패로 알린다. 현재 운영에는 빈 탭과 헤더를 준비했다.

## 해제와 실패 처리

로그아웃 시 서버의 기기 키를 취소하고 쿠키와 업무 상태를 지운다. 브라우저의 이전 응답이
늦게 도착해도 삭제 확인 전에는 자동 복원하지 않는다. 서버 취소 확인이 실패하면 안내하고
현재 서버 세션에서 재시도한다. 쿠키 저장이 차단되거나 기기 저장에 실패해도 비밀번호로
완료한 현재 로그인은 유지한다. 비밀번호·지점·권한·활성 변경은 계정 개정을 바꾸므로 이전
기기 키와 이미 열린 화면의 다음 보호된 작업도 거부한다.

## 검증

`tests/test_remember_login.py`는 발급·만료·변조·해제·계정 변경·안전한 오류를 확인한다.
`tests/test_remember_ui.py`와 실제 Streamlit 화면 검사는 복원·오래된 응답·로그아웃·저장
차단·비밀번호 입력 정리를 검사한다. `node scripts/smoke_cookie_bridge.mjs`는 실제 컴포넌트
스크립트를 가상 쿠키 저장소에서 실행해 저장·재열기·삭제·origin·만료 상한·저장 차단을
확인한다. 가상 저장소 검증을 운영 브라우저의 실제 계정 자동 로그인 성공으로 간주하지 않는다.
