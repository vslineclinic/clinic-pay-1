# 일자별 정산 기록

하루 정밀 분석이 끝나면 지점·수납일별 요약을 별도의 비공개 구글시트에 저장한다.
왼쪽 **정산 기록**에서 지점과 조회 월을 고르면 그 달의 최신 결과를 하루 한 줄로 본다.
전체 합계·채널별 부호 있는 차이, 환자 검증 건수, 추가 카드 검토 건수, 확인 시각을 표시한다.

같은 날짜를 재정산하면 새 분석 이력이 쌓이고 월별 목록은 마지막 저장 결과를 보여 준다.
응답 유실 재시도는 같은 분석 ID를 쓰므로 목록에 중복 날짜가 생기지 않는다. Sheets에는
동시 재시도의 물리적 중복 행을 막는 고유키가 없으므로 조회 시 분석 ID를 중복 제거한다.
과거 기록은 덮어쓰거나 삭제하지 않는다. 최신 결과는 Streamlit 서버에서 고정한 분석 완료
시각을 기준으로 정하며 동률이면 시트의 추가 순서를 쓴다. 저장에 실패한 이전 분석을 늦게
재시도해도 더 최근 분석 결과를 되돌리지 않는다. 브라우저의 시계는 사용하지 않는다.

**일치**는 제공된 세 자료의 비교 결과다. 채널 차이·환자 검증·추가 카드 검토·탐색 한도·
지점 교차검증·일일마감 금액 인식 경고가 있으면 **검토 필요**, 단말기 미제공이면
**단말기 미검증**으로 남긴다. 월별 표에 탐색 한도·교차검증 보류 등의 검토 사유도 표시한다.
**기록 없음**은 휴진 여부나 정산 누락을 뜻하지 않는다. 원본을 수정한 뒤에는 재정산해야
저장 기록에도 반영된다. 수동 검토 완료를 판정하지 않으며 기간 분석은 이 기록에 저장하지 않는다.

환자 이름·차트번호·승인번호·카드번호·원본 파일·파일명·메모·AI 보고서는 저장하지 않는다.
아이디·비밀번호로 로그인한다. 총괄관리자는 지점별로 전체를 보고 지점 계정은 본인 지점의
요약만 본다. 지점 계정의 선택·조회·저장 범위는 서버에서 제한한다. 계정 관리는
`docs/BRANCH_ACCESS.md`를 참고한다.

처음에는 소유자만 접근하도록 만들었고, 사용자가 기록 서비스 계정의 편집 권한과 Streamlit
인증을 연결했다. 실제 요약 저장을 확인했으며 별도 `계정` 탭도 사용한다. 공개 링크 읽기는
쓰기 인증을 대신하지 못한다. 기존 6지점·7개 일일마감 원본의 공유 권한과 링크 연결은 변경하지 않는다.

## 운영 연결 — 한 번 설정

1. Google Cloud에서 **Google Sheets API**를 활성화하고 기록 전용 서비스 계정을 만든다.
   Google Cloud 프로젝트의 Editor/Owner 역할이나 도메인 전체 위임은 필요하지 않다.
   공식 절차: <https://developers.google.com/workspace/guides/create-credentials?hl=ko>
2. 기록 전용 서비스 계정의 JSON 키를 운영자가 직접 생성·다운로드한다. 키 파일은 채팅이나
   Git에 올리지 않는다. 위 **새 기록 시트 하나에만** JSON의 `client_email`을 편집자로 추가한다.
3. Streamlit 앱 관리 → Settings → Secrets에서 기존 설정을 보존하며 아래 두 최상위 값을
   추가한다. `[clinic_daily_sheets]`나 다른 `[table]` 위에 넣어야 한다. 기존 `APP_PASSWORD`,
   `GOOGLE_API_KEY`, `FILE_PASSWORD`가 있으면 그대로 둔다.

```toml
HISTORY_SHEET_ID = "1Du6fK7YogVMvQEDC4FAXVzsldCgWLaf6lu7oLyjtGzM"
HISTORY_SERVICE_ACCOUNT_JSON = '''
다운로드한 JSON 파일의 전체 내용을 이 줄 대신 붙여넣으세요
'''
```

4. 운영자가 직접 Secrets 저장을 완료한다. Google의 기존 `[gcp_service_account]`를 추가하면
   원본 읽기 경로도 바뀌므로 기록 인증에는 사용하지 않는다. 공식 Streamlit 절차:
   <https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management>
5. 앱의 **정산 기록**에서 빈 월이 정상 조회되는지 확인하고, 합성 자료로 하루 정산 → 누적
   저장됨 → 새 브라우저 세션 월별 조회를 확인한다. 실자료를 이용한 진단 로그를 출력하지 않는다.

계정 저장소 연결이 없으면 로그인을 열지 않는다. 분석 중의 기록 저장 오류는
분석 결과를 지우지 않으며 성공 응답 전에 저장 완료라고 표시하지 않는다. 저장 재시도 버튼으로
동일 분석을 다시 보낼 수 있다. 미저장 상태에서 새 파일로 초기화하거나 창을 닫으면 그 분석을
다시 실행해야 한다. 인증 오류를 공개 링크나 서버 임시 디스크 저장으로 우회하지 않는다.

## 구조와 운영 제한

`reconciliation_history.py`는 기존 `google-auth[requests]`로 인증한다. Sheet 값은 `RAW`로
추가해 문자열을 수식으로 실행하지 않는다. 헤더·날짜·금액·요약 구조를 검증하며 손상된 기록을
조용히 제외해 일치처럼 보이지 않는다. 기록 시트의 열·헤더를 임의로 바꾸지 않는다.
서버 로컬 파일이나 Streamlit 세션을 영구 저장소로 사용하지 않는다. 사용자·지점 권한과 계정
관리는 `branch_access.py`에서 처리한다. 직원별 상세 감사 로그와 수동 확인 완료 표시는 제공하지 않는다.
