# 전체 화면 B 수납원장

## 비교 방법

- A: `https://vsline-clinic-pay-1.streamlit.app/`
- 앞선 간단 목록 B: `https://vsline-clinic-pay-1.streamlit.app/?ledger_view=web`
- 전체 화면 B: `https://vsline-clinic-pay-1.streamlit.app/?ledger_view=full-web`

총괄관리자 계정으로 로그인한다. 직원에게 공개하지 않는다. A와 전체 B는 같은 전용 원장을 사용하므로
같은 지점·날짜의 수정은 양쪽에서 보인다. 합성 거래로 비교한 뒤 시험 거래는 사유를 남겨 취소한다.

전체 B는 concept 사이트의 전체 화면 구성과 수납·환불 등록창을 사용한다. 14개 결제수단,
여신·강언 체크, 원수납 연결 환불, 날짜별 기록, 변경 이력, 마감/재개방, 백업을 기존 저장 엔진에 연결한다.
예시의 신환/구환·외국인·직원 항목은 현재 원장 스키마에 없으므로 저장되는 것처럼 표시하지 않는다.
대조·AI 분석은 전체 B 안에서 직접 실행한다. 대조 작업대에서 하루 정밀 분석·기간 분석을 선택해
단말기 마감·일일마감·베가스 수납 파일을 올린다. 일일마감은 현재 원장·구글시트·업로드 중 선택하며,
기존 암호화 파일·서버 기본 암호·지점/수납일 검증을 그대로 사용한다. 결과의 거래 대조·환자별 검증·AI 설명·
엑셀/CSV 다운로드·월별 정산 기록도 같은 B 경로와 로그인 안에서 사용한다.
기간별 기록은 수납원장 기록이고, 정산 기록은 대조 결과 요약이다. 데모의 단순 계산을 실제 분석으로 쓰지 않는다.

## 입력과 저장

- 타이핑·검색·창 열기는 브라우저 내부에서 처리한다. 키 입력마다 Streamlit 체크포인트를 보내지 않는다.
- 입력을 멈추고 1.2초 뒤 저장한다. 연속 입력은 최대 5초 간격으로 묶되 한글 조합 중에는 전송하지 않는다.
- 변경 조회는 백그라운드에서 수행하며 편집 중인 값이나 진행 중인 저장을 덮지 않는다.
- 서버 ACK 이전에는 저장완료라고 표시하지 않는다. 실패한 요청은 같은 요청 ID와 내용을 재전송한다.
- 다른 작업자가 같은 행을 먼저 저장하면 충돌로 표시한다. 현재 값을 확인한 뒤 다시 편집한다.
- 아직 서버로 보내지 못한 입력은 브라우저 메모리에만 있다. 새로고침·창 닫기는 미저장 경고를 확인한다.
  서버가 수신한 미완성 입력은 기존 초안 저장 경로를 사용한다. 환자 자료를 localStorage에 보관하지 않는다.

Neon이 지연의 원인이라고 확정하지 않는다. 기존 화면은 키 입력별 Streamlit 재실행, 작업별 계정 시트 조회,
작업별 DB 연결이 있었으며 concept은 서버에 저장하지 않는 메모리 데모였다.
전체 B도 저장·권한 재검증·동료 변경 조회에는 네트워크 시간이 필요하다. 실제 저장 응답 시간과
화면 입력 반응을 구분해 비교한다. 성능 향상률은 실제 배포 측정 전에는 제시하지 않는다.

## 현재 Streamlit 배포

`development.py`의 `ledger_view=full-web` 경로가 `web_bridge.py`를 실행한다.
원장 UI는 하나의 안정된 컴포넌트에 유지되고, `bridge-api.js`가 API 요청만 서버에 전달한다.
파일 분석은 `workspace=workbench|period|analysis|reconciliation-history`의 같은 B 진입점에서
기존 검증 엔진과 Streamlit의 파일 업로드/다운로드를 재사용한다. `reconciliation_workspace.py`와
전용 CSS가 B의 남색 메뉴·보라색 버튼·카드와 가독성을 유지한다. `ledger_view=table`로 전환하지 않는다.
선택 지점·영업일·원장 개정은 서버에서 다시 읽어 전달하며 미완료 초안이 있으면 진입을 막는다.
키 입력으로 재실행하지 않지만 조회·저장 요청 때는 Streamlit 전송 경로를 사용한다.
기존 Streamlit Secrets의 계정 및 전용 `DATABASE_URL`을 그대로 사용하므로 새 인증 정보 입력은 필요하지 않다.
원래 운영 저장소 `clinic-pay`와 원래 운영 주소는 변경하지 않는다.

## 선택형 독립 Python 서버

`web_server.py`는 동일 UI를 동일 출처 HTTP API로 제공한다. 이 서버는 현재 Streamlit 배포와 별개다.
별도 Python 호스팅에서 사용할 수 있도록 작성했으며, 실제 독립 호스팅 연결 완료와 구분한다.

```bash
pip install -r requirements-web.txt
uvicorn web_server:create_app --factory --host 0.0.0.0 --port 8000 --workers 1
```

서버 환경 변수 `PUBLIC_ORIGIN`(정확한 HTTPS 출처), `DATABASE_URL`, `HISTORY_SHEET_ID`,
`HISTORY_SERVICE_ACCOUNT_JSON`을 해당 호스팅의 보안 설정에 등록한다. 비밀번호·서비스 계정 키를
Git·프런트엔드·빌드 결과에 넣지 않는다. 원장 DB는 현재 전용 DB를 사용한다.

API는 총괄 권한 재검증, Origin/CSRF 검사, HttpOnly/Secure/SameSite 세션 쿠키, 요청 크기 제한을 사용한다.
세션은 프로세스 메모리에 있으므로 **한 worker로 운영**한다. 재시작하면 다시 로그인해야 한다.
공유 세션·공유 로그인 제한 저장소 없이 worker 수를 늘리지 않는다. DB의 이미 저장된 원장은 재시작과 별개다.
인증 시트는 읽기에만 사용하며 계정·운영 정산기록·기기 로그인 탭을 수정하지 않는다.

2026-10-17: AISPACE 연결의 공간 조회가 Internal error로 실패해 별도 호스팅 배포 대상은 확정하지 못했다.
Sites는 이 Python 서버를 직접 실행하는 경로가 아니며, 비교 페이지는 가상 자료임을 항상 표시한다.

## 검증 범위

회귀 검사는 합성 자료로 API 권한·CSRF·개정 충돌·멱등 재시도, 날짜 전환, IME,
저장 대기 중 추가 입력, 64비트 정수 금액과 Streamlit 컴포넌트 경로를 확인한다.
최종 실행 결과는 DEVLOG 및 해당 PR CI를 따른다. 실제 여러 브라우저의 동시 입력 속도와
독립 Python 호스팅의 실계정 로그인은 이 문서만으로 검증 완료라고 보지 않는다.
