# Clinic Pay 1 개발 배포와 확인 범위

## 분리 원칙

- 새 저장소: `vslineclinic/clinic-pay-1`.
- 새 Streamlit 앱: 이 저장소의 검증된 브랜치, **`development.py`**로 배포. 권장 Python 3.13.
- 기존 `vslineclinic/clinic-pay`와 기존 Streamlit 주소는 수정·재배포하지 않는다.
- 기존 계정의 총괄 역할 `admin/all`만 새 앱에 로그인할 수 있다. 지출앱의 메뉴도 총괄만 보인다.
- 지출앱과 정산앱은 현재 별도 로그인이다. 메뉴 연결이 SSO를 의미하지 않는다.

## 새 앱 Secrets

`.streamlit/secrets.toml.example`은 값 없는 예시다. 실제 값은 새 Streamlit 앱의 Secrets 화면에만 넣는다.
테이블 선언(`[... ]`)보다 위에 최상위 설정을 둔다.

| 설정 | 사용처 |
|---|---|
| `HISTORY_SHEET_ID`, `HISTORY_SERVICE_ACCOUNT_JSON` | 기존 계정 검증용 읽기. 개발 진입점은 운영 계정·기기·정산기록을 쓰지 않는다. |
| `DATABASE_URL` | 이 개발 앱 전용 PostgreSQL. 원격 연결은 TLS 필수. 운영/지출 DB를 재사용하지 않는다. |
| `GOOGLE_API_KEY` | 선택, 기존 AI 분석 기능. 미설정 시 코드 기반 대조는 사용할 수 있다. |
| `FILE_PASSWORD` | 선택, 기존 암호화 파일 기본 암호. |
| `[clinic_daily_sheets]`, `[gcp_service_account]` | 기존에 사용하던 override가 있을 때만 같은 읽기 설정을 적용한다. |

DB 설정이 없으면 원장 저장과 개발 분석기록 저장은 중지되고 연결 안내가 표시된다.
Streamlit 서버 디스크를 영구 보존 공간으로 대신 사용하지 않는다.
DB 연결/비밀번호 오류의 원문은 사용자에게 표시하지 않는다.

## 원장 동작

1. 지점과 영업일을 선택한다. 새 행에 차트번호·성명·결제 금액을 입력한다.
2. 입력이 멈춘 뒤 약 400ms 또는 입력칸을 벗어날 때 행별 저장 요청을 보낸다. 한국어 조합 중에는 전송하지 않는다.
3. `저장 완료`는 서버가 저장을 확인한 뒤 표시한다. 입력 중/전송 중/실패/충돌은 구분한다.
4. 잘못된 숫자 등은 검토할 초안으로 보존하며 정상 정산 합계에 넣지 않는다. 다른 사용자에게 초안 원문을 노출하지 않는다.
5. 여신·강언 사용은 행의 체크박스로 처리한다. 사용 체크 자체는 매출 금액을 추가하지 않는다.
6. 같은 행을 동시에 고치면 먼저 저장된 개정을 기준으로 충돌을 알리고, 뒤늦은 수정으로 덮어쓰지 않는다. 동일 요청 재시도로 중복 거래를 만들지 않는다.
7. 환불은 같은 지점의 원거래와 연결한다. 이전 날짜 원거래도 조회할 수 있으며, 결제수단별 누적 환불 한도를 다시 검사한다.
8. `대조 분석에 사용`은 현재 원장 개정으로 기존 단말기·베가스 비교를 실행한다. 원장이 바뀌면 이전 분석이 오래되었음을 표시한다.
9. 마감은 초안이 없는 최신 개정만 확정하고 원장 스냅샷을 남긴다. 재개방과 거래 제외에는 사유가 필요하다.

주기적인 화면 갱신 목표는 약 2초이며 서버·네트워크 지연에 따라 달라진다.
브라우저에서 아직 보내지 못한 입력은 DB 백업에 포함되지 않는다. 저장 상태를 확인한 뒤 작업을 종료한다.

## 기록과 백업

- 날짜별 원장·변경 전후·행위자·마감 스냅샷·개발 정산 요약은 전용 DB에 보존한다.
- 백업 내보내기는 일관된 DB 스냅샷과 SHA-256 검증값을 포함한다. **마감 스냅샷과 독립 백업은 다른 기능**이다.
- 체크섬은 파일 손상 검사용이며, 암호화·위변조 서명으로 표시하지 않는다. 내보낸 파일에는 수납 정보가 있으므로 접근이 제한된 저장 공간에서 관리한다.
- 복원 검증은 빈 새 로컬 파일에서만 허용한다. 운영 DB 덮어쓰기 복원 버튼은 제공하지 않는다.
- 자동 원격 백업/보관기간/시점복구는 DB 제공자에서 별도 설정해야 한다. 이 코드 배포만으로 켜지지 않는다.
- 실제 사용 전, 전용 DB의 자동 백업을 설정하고 합성 거래로 별도 DB 복원 시험을 마친다.

## 검증과 남은 운영 확인

```bash
python -m pytest -ra
python scripts/smoke_streamlit.py
python scripts/smoke_development.py
node scripts/smoke_cookie_bridge.mjs
node scripts/smoke_ledger_component.mjs
```

GitHub Actions는 Python 3.11/3.12/3.13과 PostgreSQL 서비스로 검사한다.
PostgreSQL 테스트는 전용 `LEDGER_TEST_DATABASE_URL`이 없으면 건너뛴다. SQLite 통과를 원격 DB 통과로 보고하지 않는다.
최신 실행 결과는 `docs/DEVLOG.md`와 GitHub Actions를 확인한다.

직원 공개 전에는 실제 두 브라우저 동시 입력·연결 끊김·새로고침·날짜 전환, 실제 파일 양식별 회귀,
원격 DB 지연·용량, 백업 복원, 관리자 권한 취소를 새 배포에서 확인해야 한다.
지출앱의 선택적 `SETTLEMENT_APP_URL`에는 검증한 새 HTTPS `*.streamlit.app` 주소만 설정한다.

## 로컬 시험만 하는 경우

`ALLOW_LOCAL_LEDGER = true`와 절대 경로 `LOCAL_LEDGER_PATH`를 함께 명시한다.
로컬 모드는 화면에 따로 표시되며 클라우드 영구 저장 또는 백업으로 간주하지 않는다.
합성 자료만 사용하고 SQLite 파일과 실제 Secrets는 Git에 올리지 않는다.

## 현재 범위에서 제외된 것

지출앱 메뉴·권한 연결 외에 식비/지출 데이터의 DB 통합과 계정 SSO는 구현하지 않았다.
Google 시트의 모든 수식·비고·서식이 새 원장에 동등하게 반영됐다는 검증도 아직 끝나지 않았다.
실제 지점별 시트 기능표를 확정한 뒤 누락 기능을 추가하고, 승인한 시점에만 기존 앱 이관과 직원 공개를 진행한다.
