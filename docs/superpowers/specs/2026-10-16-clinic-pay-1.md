# Clinic Pay 1 격리 개발 설계 — 2026-10-16
사용자가 2026-10-16 검토 보고서의 개선·확장 구현을 승인했다. 새 저장소 clinic-pay-1과 새 Streamlit 주소에서 개발하고 기존 clinic-pay 배포는 변경하지 않는다. 지출앱 정산 메뉴는 총괄에게만 노출한다.

## 구조
- 최신 clinic-pay a8b1c6ebabc9c5f882eb0916646b032c0ae3ef3c 소스 재사용. clinic-pay-1의 기존 3파일과 커밋 이력은 Git 부모 이력에 보존한다.
- 새 진입점 development.py. 기존 app.py의 계산·파일·로그인 동작은 재사용하되 개발 모드의 화면과 저장 경계를 추가한다.
- 새 원장은 전용 PostgreSQL DATABASE_URL. 명시적 LOCAL_LEDGER_PATH가 있을 때만 로컬 SQLite 시험 허용. 설정 없으면 원장 쓰기 차단. 운영 저장과 혼합 금지.
- 기존 Google 계정 인증은 읽기 전용 재사용 가능. 개발 앱은 admin/all만 허용. 원본 계정 관리·기기 발급·정산 요약 쓰기 경로는 개발 모드에서 차단하거나 새 DB로 연결한다. 기존 일일마감 원본은 읽기 전용.
- 기능 단위 별도 Python 모듈: receipt_ledger.py(저장/검증), ledger_ui.py(화면/동시 입력), ledger_component.py 및 assets/ledger_editor/(자동 저장 컴포넌트), development.py(시작), 분석 개선은 app.py 및 작은 helper.
- 서버 업무 권한은 기존 Principal 및 최신 계정 재검증 callback 사용. 브라우저 역할·날짜는 신뢰하지 않는다. 지점은 CANONICAL_BRANCHES 7개만.
- 비용 발생하는 외부 DB 서비스 생성과 비밀값 입력은 현재 미완료. 코드는 준비하고 연결 상태를 사실대로 표시한다.

## 원장과 동시 저장
- 지점+KST 영업일로 분리. 서버 UTC 저장 시각, stable UUID, 거래 개정, 일자 개정.
- 결제수단은 기존 canonical 채널; 금액은 정수 원. 여신/강언 사용 checkbox는 사용 표시이며 금액을 자동 생성하지 않는다.
- 원장 변경은 행 단위; revision CAS, request_id idempotency, actor와 이전/이후 값 audit를 원자적으로 저장.
- 정식 수납과 불완전 초안 분리. 초안은 사용자/지점/날짜 범위. 잘못된 숫자를 0원으로 바꾸지 않는다.
- 컴포넌트는 입력 멈춤 1초, Enter·다른 행·원장 밖 이동에 요청; 같은 행의 칸 이동은 묶음 처리. 한 거래 요청 순서 유지, ACK 뒤 저장완료. 실패/충돌 때 내 입력 보존.
- 다른 사용자의 저장 반영은 약 5초 간격 조회; 편집 중인 값은 덮지 않음. 내 저장은 이 조회 주기를 기다리지 않으며 ACK를 같은 실행에서 전달해 전체 앱 재실행을 피함.
- soft void 또는 명시적 연결 환불. 환불 누적은 원거래 금액 초과 불가. 기존 원거래 삭제로 환불 표현 금지.
- 마감은 일자 revision을 검사하고 같은 transaction에 snapshot 저장/닫힘 전환. 닫힌 일자 일반 수정 거부. 사유 있는 재개방, 이전 snapshot 유지.

## 이력과 분석
- 날짜 범위, 일별 원장/확정/검토 상태, 변경자/변경 전후, 마감 개정 비교.
- 기존 DataFrame 형식으로 투영해 원장→기존 대조 함수 연결. 분석 시 원장 revision 저장, 이후 변경되면 다시 분석 필요.
- 원본 누락과 0건 구분. 날짜 일부 누락도 차단/표시.
- 동일 분석의 검증·AI 입력 재사용, 엑셀은 요청 시 생성. 단일 실행 내 중복 인증 GET 감소; 보호된 쓰기마다 최신 권한 검증은 유지.
- AI 입력 범위/잘림 표시, 과도한 확정 표현 완화, 근거·금액 검증. 공용 API 키 요청 제한과 bounded backoff. AI는 자동 금액 수정 불가.
- 백업: 일관된 원장/이력 JSON export, checksum 검증, 별도 로컬 DB 복원 시험 제공. 이는 독립 원격 자동 백업이 아니다. 원격 DB 및 독립 백업 연결/복원 검증 전 실자료 운영 준비 완료로 표시하지 않는다.

## 지출앱
- 기존 디자인 유지. 총괄 역할만 정산 메뉴와 /settlement 허용.

- 검증된 새 Streamlit URL만 SETTLEMENT_APP_URL로 연결, 생성 전에는 개발 준비 상태.
- 다른 지출 업무·기존 데이터는 이 작업에서 변경하지 않음.

## 검증
- 기존 pytest/AppTest 유지. 합성 데이터만 사용.
- 동시에 같은 거래/다른 거래 수정, 응답 유실 재시도, 닫힘과 저장 경합, 날짜 분리, 권한 취소, invalid draft 보존, checkbox 중복 처리를 검증.
