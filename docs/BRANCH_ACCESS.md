# 지점별 로그인과 정산 기록 권한

직원은 자기 지점의 정산과 누적 기록을 이용한다. 총괄관리자는 모든 지점의 기록을 지점별로
선택해 조회하고 지점 계정을 관리한다. 여러 지점을 날짜 하나로 합치지 않는다.

허용 지점은 **인천점·잠실점·엔디어트·강남점·일산점·압구정·마곡점 7곳**이다.
BW컨설팅은 지점 선택·지점 계정·기록 조회/저장 대상에서 제외한다. `admin/all` 총괄 계정의
전체 지점 접근은 유지하며 기존 정산 이력은 삭제하지 않는다.

## 계정과 초기 이관

기존 비공개 기록 시트의 별도 `계정` 탭을 사용한다. `정산기록`의 기존 데이터는 변경하지 않는다.
로그인·계정 관리도 기존 `HISTORY_SHEET_ID`와 `HISTORY_SERVICE_ACCOUNT_JSON` 인증을 사용하므로
새 서비스 계정 키나 Streamlit Secrets 추가는 필요하지 않다.

2026-10-15 지출관리앱의 계정 15개를 비밀번호 검증값까지 그대로 이관했다. 비밀번호 원문을
복원하거나 Git에 저장하지 않았다. 원본에서 총괄관리자인 계정 2개만 정산앱 총괄 권한을
부여했고, `branch_admin`과 `staff`는 모두 소속 지점 전용 계정으로 이관했다. 원본에 직원
계정이 없는 잠실점은 사용자 지정 초기 비밀번호로 1개 생성했다. 아이디 목록은 총괄의 계정 관리
화면에서 확인하고 초기 비밀번호는 운영자에게 별도로 인계한다. 공개 소스의 예시에 넣지 않는다.

이관은 한 번 복사하는 방식이다. 이후 지출관리앱과 정산앱의 계정·비밀번호 변경은 별개다.
지출관리앱의 원본 계정·권한·비밀번호와 기존 일일마감 7개 파일의 공유는 변경하지 않았다.

로그인 화면의 선택형 **로그인 유지 · 최대 180일**은 비밀번호 대신 기기 키를 사용한다.
동일한 비공개 시트의 `로그인기기` 탭에는 해시만 저장하고 매 작업에서 최신 계정·기기 키를
검증한다. 로그아웃·계정 개정 변경 시 해제한다. [장기 로그인 운영](PERSISTENT_LOGIN.md)을 참고한다.

`계정` 탭의 헤더는 다음 순서를 유지한다.

```text
username, role, branch, password_hash, active, revision, updated_at
```

`role=admin, branch=all`은 총괄관리자, `role=branch`는 한 지점만 허용한다. 활성 여부는
`1`/`0`, 변경 식별자는 UUID, 변경 시각은 UTC ISO 문자열이다. 변경은 기존 행을 덮어쓰지
않고 새 개정으로 추가한다. 앱이 매번 최신 계정을 읽고 이전 개정의 로그인 세션을 거부한다.
동시 관리 요청에는 읽은 개정을 검사하지만 Sheets에 원자적 비교·갱신 기능이 있는 것은 아니다.
총괄 계정의 역할·지점·활성 여부는 지점 계정 편집 기능으로 변경하지 않는다.

기존 PBKDF2-HMAC-SHA256 100,000회 형식은 호환 검증하며 새 비밀번호는 임의 salt와
600,000회 형식으로 저장한다. 로그인 세션에는 비밀번호 원문·검증값을 보관하지 않는다.
잘못된 비밀번호·사용 중지·알 수 없는 역할·지점과 손상된 계정 형식은 접근을 거부한다.
반복 실패 제한은 서버 프로세스에서 공유한다. 여러 서버로 확장하면 제한 저장소도 공통화해야 한다.

## 화면과 서버 권한

| 기능 | 총괄관리자 | 지점 계정 |
|---|---|---|
| 하루 분석 | 지점 선택, 구글 연결 또는 일일마감 파일 | 본인 지점 구글 연결로 고정 |
| 기간 분석 | 허용 지점 선택 | 본인 지점 구글 연결로 고정 |
| 누적 기록 | 지점별 선택 조회 | 본인 지점만 조회 |
| 기록 저장 | 분석한 지점으로 저장 | 본인 지점만 저장 |
| 지점 계정 관리 | 생성·비밀번호 변경·중지 | 접근 불가 |

지점 계정은 다른 지점을 고르는 입력 자체를 제공하지 않는다. 화면 값이 변조되거나 이전
세션의 지점이 남아 있어도 구글 링크 읽기와 기록 조회·추가 전에 서버가 다시 권한을 검사한다.
분석 결과는 분석 당시 사용자·계정 개정·지점에 묶는다. 로그아웃·계정 변경·사용 중지·비밀번호나
권한 변경 시 원본 업로드, 분석 결과, Google/AI 캐시와 위젯 값을 모두 정리한다. 새 자료로
다시 시작할 때만 검증된 로그인은 유지한다. 이전 `_access_digest`는 새 권한으로 승격하지 않는다.

지점의 Google 연결이 없거나 설정에서 비활성화되어 있으면 다른 링크나 내장 기본 링크로
돌아가지 않는다. 구글 일일마감은 지점의 신뢰 가능한 입력이며, 지점 직원의 일일마감 업로드는
다른 지점의 두 파일을 함께 잘못 올리는 경로를 막기 위해 제공하지 않는다. 단말기·베가스 파일은
사용자가 내려받은 파일이므로 기존 날짜·교차검증도 통과해야 한다. 파일 내용만으로 병원 소속을
완전히 입증하는 기능은 아니다. 지점별 원본 파일을 정확히 내려받아 사용한다.

기존 Google 공유 링크의 공개 범위는 그대로다. 정산앱의 권한은 앱 안의 접근을 제한하며
Google 원본의 기존 공유 권한을 대신하거나 회수하지 않는다.

## 운영 확인

1. 총괄 계정으로 로그인해 지점별 기록 조회와 계정 관리 화면을 확인한다.
2. 각 지점 계정으로 로그인해 자기 지점명만 보이고 다른 지점 선택이 없는지 확인한다.
3. 자기 지점의 날짜를 선택해 구글 일일마감을 불러오고 같은 지점의 베가스 자료로 분석한다.
4. 기록에 자기 지점·검증된 수납일이 저장되는지 확인한다.
5. 로그아웃 후 다른 지점 계정으로 접속해 이전 자료·결과·다운로드가 남지 않는지 확인한다.

계정 탭을 직접 편집하기보다 총괄관리자 화면을 사용한다. 비밀번호 검증값과 JSON 키를
공유 문서·소스·스크린샷에 노출하지 않는다. 계정 저장소의 공유는 기록용 서비스 계정과
소유자에게만 유지한다.
