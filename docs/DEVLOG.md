# 개발일지 (DEVLOG)

**여러 계정이 번갈아 개발하는 저장소다.** 각 작업 세션이 무엇을 왜 바꿨는지 시간순으로
남겨, 다음 세션·다른 계정이 맥락을 잃지 않게 한다.

- **DEVLOG**(이 파일) = 시간순 기록 — *무엇을 왜 했나*. 항목은 지우지 않고 계속 쌓는다.
- **`HANDOVER.md`** = 현재 상태 스냅샷 — *지금 어떻게 생겼나*. 구조가 바뀌면 갱신한다.
- **`CLAUDE.md`** = 작업 규칙 — 어느 계정이든 이 저장소를 열면 따라야 할 규약.

## 기록 방법

코드를 바꿨으면 **아래 템플릿을 복사해 `## 최근 작업` 바로 밑에 추가**하고, 코드와 **같은
커밋**에 포함시킨다(별도 커밋으로 미루면 누락된다).

```markdown
### YYYY-MM-DD · <한 줄 제목> (PR #NN)

- **왜**: 어떤 문제/요구가 있었나 (개인정보 없이 합성 사례로 설명)
- **무엇**: 실제로 바꾼 것 (함수·섹션 단위로)
- **결정**: 선택지가 있었다면 무엇을 왜 골랐나 / 무엇을 일부러 안 했나
- **영향**: 건드린 파일 · 테스트 수 · 주의할 부작용
- **남은 것**: 후속 과제나 확인 필요 사항 (없으면 생략)
```

> **왜**와 **결정**을 반드시 적을 것. "무엇"만 있으면 `git log`와 다를 게 없다.
> 다음 사람이 되돌리면 안 되는 결정을 되돌리는 사고를 막는 것이 이 파일의 목적이다.
